## 1. 本周目标

计划里的 Gate 1（`04_experiment_plan.md`）：在投入约 90 次训练之前，先确认

- **Q1** 打分器是校准的（在答案已知的数据上返回理论值），且掩码模型的两把尺子彼此一致；
- **Q2** 塞进去的探针到底测不测得出来——r=16 > r=1 > 没塞过，且超过种子噪声；
- **Q3** 两种预训练目标在对齐条件下有没有差异。

次要目标：在 4090 上实测 MFU，替换计划里 10–260 GPU 小时这个巨大的不确定区间。

## 3. 试点工具 `pilot/`（8 个文件）

独立实现、纯 PyTorch，不依赖原仓库 `src/`。

| 文件 | 作用 |
|---|---|
| `data.py` | 均匀随机 DNA（GC 正好 0.5），288 字母窗口；96 字母探针嵌在各自的宿主窗口偏移 96 处，每次重复用一个新宿主；**标签跟着打乱的置换一起走**（构造时打标签，断言精确率/召回率 = 1.0）；验证集和测试集不含探针 |
| `model.py` | 4 层 pre-LN transformer，d=512，8 头，输入输出嵌入绑定，1276 万参数；`causal=True/False` **只**差一个注意力掩码 |
| `train.py` | AdamW 3e-4，warmup 100，余弦衰减到 10%，batch 64，bf16，梯度裁剪 1.0；AR 在全部 288 个位置算损失；MLM 只在被遮位置算损失（纯遮挡，不用 80/10/10）；每轮在验证集算损失；保存 `best.pt`（验证损失最低）和 `final.pt`；记录 tokens/s 和相对 165 TFLOPS 峰值的 MFU |
| `score.py` | 三个打分器 `ar`、`pll`（每个位置遮一次）、`prefix`（把 ≥i 的位置全遮住、读 i）；全部按核苷酸 log2；留出集下限检查（≥ 1.999 bit/nt）；对共享随机候选池排名，精确随机 p = rank/(n+1)；Carlini-2023 精确匹配抽取（给 48 字母前缀；AR 贪心 / MLM 严格从左到右解遮挡，都限制在 ACGT） |
| `run_pilot.py` | 一个格点从头跑到尾；`--checkpoint best\|final`、`--score_only`、`--smoke` |
| `report.py` | 汇总 `scores*.json` → Gate 1 报告（Q1/Q2/Q3、Mann-Whitney、Spearman） |
| `compare_ckpt.py` | best.pt 和 final.pt 并排比较 |
| `launch.sh`、`relaunch_mlm.sh`、`wait_and_report.sh` | 服务器端启动脚本；进程匹配模式不出现在 SSH 命令行里 |

设计不变量：全程没有 padding（定长）；探针不做位置簿记；所有指标按核苷酸；每次运行的每个打分器都断言 4.0 下限。

## 4. 运行记录

### 4.1 Smoke（GPU 1/2，各约 20 秒）
`--smoke`：400 条窗口、2 轮、候选池 30。两条路径都跑通；下限 2.013（ar）、2.026（pll/prefix）。稳态 MFU 0.33。

### 4.2 试点 v1 — 4 格点，20 轮，用 `best.pt` 打分
配置：训练集 5,000（+340 条探针宿主 = 5,340），验证 500，测试 500；每档 20 个探针 × r ∈ {1, 16} + 40 个非成员；候选池 500；种子 0/1。

| 运行 | 最佳轮次 | 训练秒 | 打分秒 | MFU |
|---|---|---|---|---|
| ar_s0 | 3 | 43 | 19 | 0.34 |
| ar_s1 | 2 | 43 | 19 | 0.35 |
| mlm0.15_s0 | 13 | 47 | 1522 | 0.32 |
| mlm0.15_s1 | 13 | 46 | 1507 | 0.33 |

下限：ar 2.0006–2.0010；pll 2.0002–2.0006；prefix 2.0002–2.0006。全部通过。
Q1：pll 与 prefix 的 Spearman 0.960–0.991（n=80）。Q2：r=16 对非成员，四个模型 MWU p = 6e-8 … 9e-8，**但效应极小**：r=16 的 bits/nt 1.992–1.995 对 2.001；rank-1 率 0–20%；抽取全部 0/20，Hamming ≈ 35/48（随机是 36）。Q3：Δ = +0.001 bit，无信息量。

**诊断。** 在随机数据上验证损失 2–3 轮就到底（2.000 bit）；之后的训练只是在背训练集，会让验证损失略微上升，所以"验证损失最低"选出的是**记忆最少**的快照。AR 的 `best.pt` 落在第 2–3 轮，几乎没训。

### 4.3 试点 v1 用 `final.pt` 重新打分（只打分，不重训）

| 运行 / r=16 | 中位排名 | rank-1 率 | bits/nt | 48 字母精确抽取 | Hamming |
|---|---|---|---|---|---|
| ar_s0 best → final | 39 → **1** | 0.05 → **1.00** | 1.992 → **0.586** | 0.00 → **0.65** | 35.2 → **2.0** |
| ar_s1 best → final | 34 → **1** | 0.20 → **1.00** | 1.993 → **0.664** | 0.00 → **0.70** | 35.0 → **1.8** |
| mlm0.15_s0（prefix/train） | — → 12 | 0.00 | 1.994 | 0.00 | 31.2 |
| mlm0.15_s1（prefix/train） | — → 32 | 0.00 | 1.993 | 0.00 | 31.1 |

r=1（AR，final）：中位排名 48–77，rank-1 率 5–10%，对非成员 MWU p = 0.007–0.012。非成员：中位排名 252–290（随机），无误报。下限：ar 2.021–2.022（轻微过拟合，仍 ≥ 2.0）；pll/prefix 2.0004–2.0005。

### 4.4 试点 v2 — 4 格点，50 轮，档位 r ∈ {1, 16, 64}，用 `final.pt` 打分
训练集 5,000 + 1,620 条宿主 = 6,620（24% 的窗口带探针——已记录，正式网格不会这么高）。

**因果（ar_s0 / ar_s1）：** 留出集下限 3.14 / 2.89 bit（严重过拟合，仍 ≥ 2.0）。r=1：rank-1 100%，bits 0.74 / 0.90（训练宿主）、1.49 / 1.33（新宿主），精确抽取 5%。r=16：bits 0.08，rank-1 100%，抽取 100%。r=64：bits 0.06，抽取 100%。非成员：排名 251–268，bits 4.4–4.6（模型给没见过的数据的似然*低于*随机）。

**掩码@0.15（s0 / s1）：**
- `pll`：下限 2.0006–2.0008。r=1 无信号（排名 157–304）。r=16 排名 12–16，rank-1 率 30–45%，bits 1.985–1.990。r=64 排名 1，rank-1 100%，bits 0.099 / 0.134，z ≈ +285…+342。精确抽取：r=64 **15–20%**，r≤16 为 0%。
- `prefix`：下限 **2.037 / 2.054**（偏离零点）；非成员 bits 2.10 / 2.14；r=16 bits 2.10 / 2.25（**比随机还差**，排名 288–331）；r=64 bits 1.05 / 1.24，rank-1 95–100%。
- 50 轮时的 Q1：pll 对 prefix Spearman **0.40–0.69**（20 轮时是 0.96–0.99，那时两者都在底噪上）。

### 4.5 对齐条件下的 Q3（`ar/train` 对 `prefix/train`，r=16）
AR 0.081 / 0.084 bit，100% 逐字恢复；MLM 2.097 / 2.239 bit，0% 逐字恢复。Δ = +2.09 bit（种子离散 AR ±0.001，MLM ±0.07）。注意：prefix 打分器在 MLM 上偏离零点（见上）；用 `pll` 看 MLM 的 r=16 是 1.985–1.990，仍比 AR 高约 2 bit。

## 5. 发现

1. **checkpoint 选择的坑（已坐实）。** 在随机数据上按验证损失选快照，选出的是记忆最少的一轮。同一条权重轨迹，换 final.pt 打分：rank-1 率 5–20% → 100%，抽取 0% → 65–70%。网格规则：**所有合成数据格点一律给 `final.pt` 打分**；在验证集有意义的真实基因组上两者都报。原仓库也按同样规则选快照、且在测试集上选——作为其低重复档接近随机的一个可能原因，私下向 Alex 提出。
2. **低掩码率 MLM 上两把尺子不一致。** `pll` 稳在零点（2.0006）；`prefix` 漂到 2.04–2.05，并把 r=16 探针排到随机以下。**决定（你的）：两把尺子全程保留，各自做零点检查；标出来，不删掉。** 两者随掩码比例升高在哪里重新一致，是 E2 的一条结果；`prefix` 仍是 E3 对齐条件比较的工具。
3. **目标效应很大。** 同样数据、同样轮数：因果模型把 r=16 完全背下来；掩码@0.15 要到 r=64 才能 rank-1 100%，而且那时也只有 15–20% 能逐字抽出 → "存在但抽不出"，可测。掩码每轮只监督 1/6.7 的位置 → **双口径预算（固定轮数 和 固定监督 token 数）必须做**。
4. **饱和。** 因果模型 50 轮已成查表机（留出集 2.9–3.1 bit）。训练轮数是真实的实验旋钮，不是干扰项。
5. **吞吐。** MFU 0.32–0.35；90 次网格的训练 < 1 小时。瓶颈在打分：MLM 的 PLL 每次约 25 分钟（2048 行/批；4096 行 OOM，约 20 GB）。下一步优化打分。
6. **非成员探针在任何运行、任何打分器、任何快照下都没有误报。**

## 6. 遇到的问题与处理

| 问题 | 处理 |
|---|---|
| Bash heredoc 被源码里的引号绊住 | 源码用文件工具写，不用 heredoc |

| 本地 Git-Bash 的 numpy 段错误 | 项目代码只在服务器跑 |

| 计划里的 Q1 是空检验（对因果模型做 PLL ≡ 普通 AR 打分） | Q1 改为检验 MLM 模型自己的两把尺子 |

## 7. 已定的决定

- 所有合成数据格点用 `final.pt` 打分（写入 E0 作为仪器风险，补 golden test）。
- 两把 MLM 尺子都保留；结果表每把尺子加一列"零点"。
- E1/E2 必须做双口径预算。
- E2（掩码比例扫描）提升为第 4 周与 E1 并行。
- 投稿立场不变：按 NeurIPS 标准做，按 SaTML 预期投，Gate 3 再定。
